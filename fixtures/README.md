# Fixtures

Saved portal HTML, one directory per site profile: `fixtures/<site-id>/page-1.html`.

Served locally by `npm run fixtures:serve` (http://localhost:4173). **E2E tests never touch a
live portal** (§6.1) — Playwright's `baseURL` points here.

## Capturing a fixture

1. Confirm the portal's verdict in `docs/portal-notes/<site-id>.md` is `assistive-ok`.
   Do not capture fixtures for `prohibited` portals.
2. Open the form, `Ctrl+S`, save as **Webpage, Complete**.
3. Drop it in `fixtures/<site-id>/page-1.html` (one file per wizard step: `page-2.html`, ...).
4. **Strip all real PII.** Use obviously-fake values, then grep the file for anything you
   actually typed — including in `value=` attributes, hidden inputs, and `__VIEWSTATE`.
5. Note in the portal file which step each page is.

## Hostile variants

Phase 6 needs fixtures that misbehave on purpose (§ Phase 6 Verify):

- resets all field values on a simulated postback,
- regenerates element ids on each load,
- contains a fake CAPTCHA gate,
- calls `form.submit()` on load (the Phase 5 adversarial test),
- embeds a cross-origin iframe.

Name these `page-1.hostile-<what>.html` alongside the clean capture.

## demo-portal/

Hand-written, synthetic, not a copy of any real site. It exists so `fixtures:serve` and the
e2e harness have something to run against before real portals are chosen. Keep it — it is
also the "demo fixture form" the Phase 10 onboarding flow fills.

## photo-4mb.jpg

An oversized synthetic "phone photo" (3024×4032, ~3.6 MB) used by the Phase 2 derivation e2e spec.
Generated, not committed from a camera: a real photograph of a real person is exactly the PII this
directory forbids, and a stock photo would drag a licence into the repo.

Regenerate with `node scripts/make-photo-fixture.mjs`.

## _harness/

Build output of the e2e derivation harness (`tests/e2e/harness/`). Generated by
`npm run harness:build`, gitignored, and rebuilt automatically before every Playwright run.

## heldout-*/

The Phase 4 evaluation corpus. `matching/eval.test.ts` measures the acceptance gate against these
and nothing else.

**Do not tune the matcher against them.** Ground truth is a `data-expect` attribute on each control
(the matcher never reads data attributes, so annotating cannot leak into the answer). Fields that
should map to nothing carry `data-expect="unknown"`, including deliberate traps — a 10-digit numeric
box labelled "Name" that the traits veto must refuse.

These are synthetic and were written by the same hand as `synonyms.json`, so they prove the rules
generalise past *verbatim* wording, not that they generalise to real portals. Replace them with
captured pages when real fixtures exist.

## ugly-portal/

Deliberately hostile markup covering every label pattern §Phase 3 names, plus the ones that produce
a *wrong* label rather than none. Used by the harvester snapshot tests.

## hostile-portal/

The §Phase 5 adversarial fixture. `page-1.html` tries to submit itself on a timer, on every input
event, and via a scripted click once `__startHostilities()` is called — the test installs the guard
first, then turns the page loose while filling it.

`page-onload.html` is the honest counterpart: it calls `form.submit()` during load, before any
gesture-injected extension could exist, and **does** navigate. That test asserts the navigation
rather than hiding it. The guard protects from the moment it installs and not before; P2 still holds
there, because nothing had been filled yet.

## pdf/, images/ and entrance-portal/

Made-up documents and a made-up form for the document reader and the real-panel
test (`tests/e2e/panel.spec.ts`), each generated by a script beside its purpose:

- `pdf/locked-aadhaar.pdf`, `pdf/owner-locked.pdf` — `scripts/make-locked-pdf-fixtures.py`
- `pdf/scanned-three-pages.pdf` — `scripts/make-scanned-pdf-fixture.py`
- `images/passbook.jpg` — `scripts/make-passbook-fixture.py`
- `entrance-portal/page-1.html` — written by hand; an entrance application asking
  for each subject's marks and two uploads, annotated for the matching record.

Every name, number and institution in them is invented. Real documents never go
here.

## choice-portal/

Choice questions whose options never say the value the way the vault does.

- `google-form.html` — a Google Form's structure, copied: dropdowns as
  `role="listbox"` divs of `role="option"` divs with `data-value`, an open copy
  of the list to press; multiple choice as `role="radiogroup"` of `role="radio"`;
  "Other:" as `__other_option__` with its "Other response" box; Submit as a
  `role="button"` div. Its script copies the behaviour — nothing changes unless
  an option is pressed — and records each answer in a hidden `entry.N`, so a
  test reads what the page itself took.
- `native-other.html` — native dropdowns and radios: "M"/"F"/"TG", Karnataka's
  category codes, income in lakh bands, blood groups spelled out, and two
  "Others" whose boxes the filler must find (one shown only once it is chosen).

Both are annotated with `data-expect`, the "Other" boxes as `unknown`.

## images/flat-marks-card.png and images/curled-marks-card.jpg

A made-up Class 10 marks card, drawn flat by Chromium
(`scripts/make-curled-photo-fixture.mjs`) and then photographed badly by
`scripts/make-curled-photo-fixture.py`: curled, tilted, lying on a table, lit
from one side. Read as photographed, each subject's marks pair with the next
subject; flattened, each with its own — the scanner's test (Stage 2).

## images/grade-card-ruled.png and images/grade-card-open.png

A made-up semester grade card, drawn by Chromium twice — with ruled cells and
without (`scripts/make-grade-card-fixtures.mjs`) — its courses a table whose
rows start with a course code and whose first title wraps onto a second line.
Read as lines it gave only its result; read as a table (SLANet_plus, Stage 3),
its courses, their total, SGPA, CGPA and backlogs. Every name and number is
invented, and the card says SAMPLE on its face. `pdf/grade-card.pdf` is the
same card printed to a PDF by Chromium, with real text in it, as a university
portal hands one over: its table is laid out from where the text sits.

`placement-portal/grades.html` is a made-up campus placement form asking what such
a card answers — the USN, the SGPA, the CGPA and the backlogs — annotated with
`data-expect`.

## bank-portal/

`bank-portal/bank-details.html` is a made-up scholarship page for the account a
scholarship is paid into. Beside the IFSC it asks for the MICR code and the
branch's address — what RBI's list fills from the IFSC alone — and then for the
applicant's own address, so neither address box may take the other; annotated
with `data-expect`. The passbook (`images/passbook.jpg`) prints an IFSC no bank
has, SMPL0001234, and the panel test checks that RBI's list says so. The real
codes the tests look up — SBIN0000001, State Bank of India's Kolkata Main
branch, and PIN 560001, Bengaluru G.P.O. — are the addresses of a branch and a
post office, not anyone's detail.

`images/passbook-holder-block.jpg` (`scripts/make-passbook-fixture.py`) is a
made-up passbook laid out as the user's own is, and as small — 780 pixels
across, compressed: the bank's name with the branch stamped under it, an empty
"Branch Name & Address" box, the account number after "A/C No.", the holder's
name, "S/O" and address under one label, and the codes on the last line. Its
codes are the same public ones, so the lists can be checked against it.

## images/caste-certificate-seal.png and certificate-portal/

A made-up caste certificate whose issuing authority is printed only in its
seal (`scripts/make-seal-fixtures.mjs`): round, violet, stamped at an angle over
the signature, TAHSILDAR over the top and SAMPLEPURA TALUK under the bottom. Its
serif face prints 0 as a small o, which the reader reads as one — measured, and
kept. `certificate-portal/reservation.html` is a made-up central-style
reservation page asking each certificate's number, date of issue and issuing
authority under a heading that names it, and a passport's date of issue that
nothing in the vault answers.

## images/*-income-certificate.jpg and indic-portal/

Made-up income certificates printed in Hindi, Telugu and Tamil, rendered by
Chromium so their scripts are shaped as print is (`scripts/make-indic-fixtures.mjs`),
each marked SAMPLE clear of its text — a watermark across a line damages it,
which is measured and noted rather than tested away. `indic-portal/name-in-hindi.html`
asks for the name in English, in Hindi and in Kannada; the vault's Hindi spelling
answers the second and leaves the third blank.
